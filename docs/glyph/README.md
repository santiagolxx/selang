# Glyph CLI Documentation

## Overview

Glyph is the main command-line interface for the Sel programming language toolchain. It provides a unified interface for compiling Sel assembly code and running Sel bytecode programs.

## Architecture

Glyph is structured as a simple CLI application that orchestrates the compilation and execution pipeline:

```
┌─────────────────┐
│   Glyph CLI     │
├─────────────────┤
│ • Argument      │
│   Parsing       │
│ • File I/O      │
│ • Error         │
│   Handling      │
│ • User          │
│   Interface     │
└─────────────────┘
        │
        ▼
┌─────────────────┐
│   Operations    │
├─────────────────┤
│ • Compile (-c)  │
│ • Run (-r)      │
│ • Help (-h)     │
└─────────────────┘
```

## Dependencies

### External Crates
- **clap**: Command-line argument parsing
- **dialoguer**: Interactive user input prompts

### Internal Crates
- **chisel**: Compiler frontend for Sel assembly
- **sel**: Virtual machine runtime

## Source Structure

```
src/
├── main.rs         # Entry point and CLI setup
├── compiler.rs     # Compilation workflow
└── runner.rs       # Execution workflow
```

## Module Documentation

### main.rs

**Purpose**: Application entry point and command-line interface setup.

**Key Components**:
- `Args` struct: Defines CLI arguments using clap derive macros
- `main()` function: Parses arguments and dispatches to appropriate handlers

**Variables**:
- `args: Args` - Parsed command-line arguments
- `compile: Option<PathBuf>` - Path to source file for compilation
- `run: Option<PathBuf>` - Path to bytecode file for execution
- `output: Option<PathBuf>` - Output path for compiled bytecode

### compiler.rs

**Purpose**: Handles the compilation workflow from Sel assembly to bytecode.

**Key Functions**:

#### `compile(source: PathBuf, output: Option<PathBuf>)`

**Purpose**: Compiles a Sel assembly file to bytecode.

**Parameters**:
- `source: PathBuf` - Path to the input .sel file
- `output: Option<PathBuf>` - Optional output path (defaults to "a.sel")

**Workflow**:
1. Read source file content
2. Prompt user for program metadata (author, name)
3. Call `chisel::compile_source()` to generate bytecode
4. Write bytecode to output file
5. Display compilation results

**Variables**:
- `source_str: String` - Content of the source file
- `output_path: PathBuf` - Resolved output file path
- `program_name: String` - User-provided program name
- `author_name: String` - User-provided author name
- `bytecode: Vec<u8>` - Generated bytecode

**Error Handling**:
- File I/O errors are handled with `expect()` calls
- Compilation errors use Ariadne for visual diagnostics
- Process exits with code 1 on compilation failure

### runner.rs

**Purpose**: Handles the execution workflow for Sel bytecode.

**Key Functions**:

#### `run(input: PathBuf)`

**Purpose**: Executes a compiled Sel bytecode file.

**Parameters**:
- `input: PathBuf` - Path to the input .selb bytecode file

**Workflow**:
1. Display VM startup banner
2. Create VM instance with 4KiB stack
3. Read and deserialize bytecode file
4. Extract opcodes from bytecode file
5. Load program into VM
6. Execute program

**Variables**:
- `vm_instance: VirtualMachine` - VM instance with 4096 bytes stack
- `file: Result<BytecodeFile, String>` - Deserialized bytecode file
- `opcodes: Vec<OpCode>` - Extracted opcodes for VM execution

**Error Handling**:
- File reading errors exit with code 1
- Bytecode deserialization errors are displayed and exit with code 1
- VM execution errors panic with detailed error messages

## Command Line Interface

### Usage
```bash
glyph [OPTIONS]
```

### Options
- `-c, --compile <FILE>` - Compile a Sel assembly file
- `-r, --run <FILE>` - Run a Sel bytecode file
- `-o, --output <FILE>` - Specify output file for compilation
- `-h, --help` - Display help information

### Examples

**Compile a program**:
```bash
glyph -c program.sel -o program.selb
```

**Run a compiled program**:
```bash
glyph -r program.selb
```

**Compile with default output**:
```bash
glyph -c program.sel
# Creates a.sel
```

## Error Handling Strategy

### Compilation Errors
- Syntax errors are displayed using Ariadne with source code highlighting
- File I/O errors show descriptive messages
- Process exits with non-zero code for CI/CD integration

### Runtime Errors
- VM errors are caught and displayed with context
- Stack traces are available with `RUST_BACKTRACE=1`
- Critical errors cause immediate program termination

## User Experience Features

### Interactive Prompts
- Program name and author are collected interactively during compilation
- Uses `dialoguer` for consistent, user-friendly input prompts

### Visual Feedback
- Compilation success shows bytecode size
- VM startup displays ASCII art banner
- Progress indicators for long-running operations

### File Handling
- Automatic file extension detection
- Sensible defaults for output paths
- Comprehensive error messages for file operations

## Performance Considerations

### Memory Usage
- VM stack size is fixed at 4KiB (configurable in code)
- Bytecode files are loaded entirely into memory
- No streaming or lazy loading for simplicity

### Execution Speed
- Direct delegation to optimized chisel and sel crates
- Minimal overhead in CLI layer
- No unnecessary data copying or transformation
